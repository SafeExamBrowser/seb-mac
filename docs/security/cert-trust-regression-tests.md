# TLS trust evaluation regression tests (CWE-295)

Regression coverage for the `authorizedHosts` substring certificate-validation
bypass in `Classes/BrowserComponents/SEBBrowserController.m`. A previously
successful `SecTrustEvaluate` must never authorize a later failed evaluation.

## What was done

1. **Fix** — removed the host-based fallback so a failed trust can only be
   overridden by an explicit public-key pin / matching debug cert.
2. **Refactor for testability** — the server-trust decision was extracted into the
   pure class method
   `+[SEBBrowserController shouldAuthorizeServerTrust:host:port:caCerts:tlsCerts:debugCerts:debugCertNames:pinEmbeddedCertificates:]`.
   It holds no cross-connection state (all inputs are parameters), so a prior
   success cannot influence a later challenge. The challenge handler now just calls
   it and builds the credential on `YES`.
3. **Test wiring** (all DEBUG-only, nothing ships in release):
   - `Classes/BrowserComponents/SEBBrowserController+Testing.h` — declares the method
     to the test bridge (imported by `OtherSources/SEB-Bridging-Header.h` under `#if DEBUG`).
   - `Classes/BrowserComponents/SEBBrowserControllerTrustTestSupport.swift` — app-module
     `@objc` bridge that builds a server `SecTrust` (leaf + `SecPolicyCreateSSL(host)`)
     and runs the production decision. Mirrors the existing
     `SEBLockdownModePolicyMigrationTestSupport` pattern.
   - `SEBTests/SEBBrowserControllerTrustTests.swift` — the XCTest matrix.
   - `scripts/gen-trust-test-fixtures.sh` — regenerates the certificate fixtures.

## Certificate fixtures

Generated by `scripts/gen-trust-test-fixtures.sh` (OpenSSL 3.x) and embedded as
base64 DER constants in the test. A test CA plus: valid `example.test`, valid
`sub.example.test`, wrong-host (`other.test`), expired `example.test`, and
self-signed `example.test`. Valid certs / CA use a far-future expiry so tests never
flake; the expired leaf is intentionally expired (issued via `openssl ca -startdate
-enddate`, since `-not_before/-not_after` are OpenSSL 3.2+ only).

## Test matrix

| Test | Scenario | pin | Expected |
|------|----------|-----|----------|
| testValidCertChainingToEmbeddedCA | valid leaf, embedded CA | both | authorized |
| testValidSubdomainCert | valid sub.example.test | false | authorized |
| testExactPublicKeyPin | pinned self-signed cert | true | authorized |
| testUnknownCASelfSigned | self-signed, unknown CA | both | rejected |
| testExpiredCert | expired leaf | both | rejected |
| testHostnameMismatch | cert for other.test served for example.test | both | rejected |
| testPinnedButPublicKeyMismatch | pin a different cert | true | rejected |
| testValidThenInvalidSameHost | valid then invalid, SAME host | both | 1st ok, 2nd rejected |
| testInvalidCertForRealSubdomain | invalid cert for sub.example.test after parent validated | false | rejected |
| testNonLabelSubstringHost | host `notexample.test` (old predicate matched) | false | rejected |
| testAttackerSuffixHost | host `example.test.attacker.test` | false | rejected |

The last four are the direct CWE-295 regression guards: the decision is stateless,
so no host relationship (same host, subdomain, non-label substring, attacker suffix)
lets a failing certificate through, for either value of `pinEmbeddedCertificates`.

## Running

Run from Xcode (Product ▸ Test, or the test navigator) — the tests use the SEB app
as their test host. Fixtures can be regenerated with
`bash scripts/gen-trust-test-fixtures.sh` and pasting the base64 into the test.
